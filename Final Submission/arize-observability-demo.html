NovaMart Support Crew · observability · 10 Sep 2026

What the traces actually say

Every finished turn exports OpenInference spans to Arize AX. This is what that data was used for: an instrumentation audit, a golden dataset built from the run sheet, and an experiment that replays all 23 scenarios against the deployed crew and scores them against their labels. Every number here came out of a command, not an estimate.

1 · How the tracing is wired

Export is in-process, at the end of each turn — server/runtime/trace.ts calls exportTurnSpans() in flush(). It is not an offline replay of the JSONL logs, though those are written too.

It is also silent when unconfigured: resolveArizeConfig() returns null with no keys and the export is skipped without a word. That is right for a turn — a broken collector must never cost a customer their answer — and wrong for an operator, who otherwise finds out by opening an empty dashboard days later. So /api/health reports it:

"arize": { "status": "enabled", "project": "novamart-support-crew" }

Only turns that call a model produce spans. The public engine is deterministic, so spans come from gated /final traffic and nothing else — an empty dashboard is not by itself evidence of a broken exporter.

The finding: no LLM spans, so no token or cost attribution

Spans are built from the runtime's own trace records — agent hops and tool calls — so the model calls themselves are never instrumented. Structurally the traces are clean, but Arize's token and cost dashboards have nothing to populate from, and latency cannot be attributed between model time and tool time.

Worth stating plainly rather than discovering during a cost review: this is a gap in coverage, not a bug in what exists. Closing it means instrumenting the SDK's model calls, not changing the spans above.

4 · Experiment: does the live crew still match its run sheet?

The task in scripts/arize-experiment-task.py replays each row against the deployed app and returns what actually happened. It derives the reviewer-gate cookie from FINAL_DEMO_PASSWORD, because /api/chat picks its engine per request — without it, every row would quietly run the keyless engine and the experiment would measure the wrong system while looking perfectly healthy. All 23 rows confirmed engine=sdk.

Read the headline number carefully

Six of the 23 rows did not run. Partway through, the Anthropic account backing the deployment ran out of credit — Claude Code returned an error result: Credit balance is too low — and those turns failed in about two seconds.

They are not scored below. They also do not look like failures at a glance, which is the more interesting part: when a turn fails the app reports done{escalated} as a fail-cautious fallback, so an outage and a genuine handoff are the same status. The tell is that a real escalation mints a ticket and a reason code; these had neither, no tools and no hop.

All three lean the same way: the crew escalated where the run sheet expected an answer, or escalated earlier in the chain than labelled. That is the same direction as the one accepted open defect, DEF-14 — a correct retrieval scoring under the grounding gate and handing off. Erring toward a human is the right direction for a support system to err in, but it is a real gap between documented and observed behaviour, and it is now measured rather than asserted.

Reproducing it

ax datasets create --name novamart-runsheet-23 \
  --space <your space id> --file runsheet-dataset.json

FINAL_DEMO_PASSWORD=… ax experiments run \
  --name runsheet-vs-live-crew \
  --dataset RGF0YXNldDozNjQ1ODc6bnZZNg== \
  --task scripts/arize-experiment-task.py --concurrency 2

ax will not resolve a project or dataset by name without --space; pass ids. Experiment RXhwZXJpbWVudDoxNDE4NTA6cG1HLw==, project novamart-support-crew.

5 · What this demonstrates

Three things that are hard to claim without data. The traces are structurally sound and prove the hop-and-tool architecture is real rather than described. The run sheet doubles as a regression suite, so "it matches the documented behaviour" became a number that can move. And the exercise surfaced two things nobody would have gone looking for: no token attribution anywhere in the traces, and a fail-cautious status that makes an outage indistinguishable from a handoff.

The second one is the one worth keeping. A support crew that escalates when it breaks is behaving correctly for its customer and lying to its dashboard.
