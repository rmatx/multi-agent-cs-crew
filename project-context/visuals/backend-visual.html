One request, two possible engines

The route handler does the work that must happen either way — parse, validate, resolve the demo clock, pump the stream — then hands off to whichever engine CHAT_ENGINE selects. Both return the same frame types, so the browser cannot tell them apart.

Who may call what

Delegation is enforced by what each agent is handed, not by what its prompt asks it to do. Only the coordinator holds the delegation tool, so a specialist cannot re-route — the rule holds even if a specialist is talked into trying.

Two guarantees the model cannot decline

Both of these were prompt instructions first. Both were observed being ignored — not often, which is what makes prompt-only enforcement dangerous. They are now decided by the runtime after the turn, on what actually happened rather than on what the model was asked to do (ADR-17).

  1. ADR-08A spent hop budget forces escalation. The hook denied the handoff and told the coordinator to escalate; at maxHops=1 it told the customer "let me get that sorted for you now, and I'll follow up shortly" and ended resolved. The engine now builds the repeat_failure package itself.
  2. NFR-SAFE-01A turn that consulted nobody has answered from memory. Asked the capital of France, the coordinator answered "Paris". A turn with no hop, no ticket and no question back is escalated as ungrounded whatever it wrote — bare greetings excepted, matched whole so "hi, where is my order" is not exempt.

The prompt rules stay. They make the model right most of the time, which is cheaper and reads better. What changed is that the guarantee no longer depends on them.

Why the crew cannot move money

The brief said no refunds, cancellations, or payments. That is enforced five times over, at layers that fail independently — none of them a line of prompt text asking the model to behave.

  1. L1Nothing bound. No refund, cancel, or payment function is written anywhere in the process.
  2. L2Read-only driver. DuckDB is opened in read-only mode; a write cannot reach the data.
  3. L3Startup assertion. The registered tool set must equal a hard-coded literal, or the server refuses to start.
  4. L4PreToolUse denial. Money vocabulary and non-allowlisted tools are refused at call time.
  5. L5canUseTool gate. A second, independent runtime check that does not share code with L4.

The guarantee is tested, not asserted: injecting an issue_refund tool into the registry takes the suite from 9 passing to 7 passing and 2 failing. Then it goes back.

What running it actually found. Nine defects, every one from a live turn rather than a review: a coordinator answering from memory, a hop budget that denied without forcing, a registered tool no agent could call, two assistant messages run together mid-sentence, and three separate retrieval faults in the policy scorer — including a stemmer where received and receives never met, so the crew escalated questions the corpus answers word for word. All fixed, all regression-tested. The threshold was never moved to make one pass.
