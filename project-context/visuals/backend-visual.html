One request, two possible engines

The route handler does the work that must happen either way — parse, validate, resolve the demo clock, pump the stream — then hands off to whichever engine CHAT_ENGINE selects. Both return the same frame types, so the browser cannot tell them apart.

Who may call what

Delegation is enforced by what each agent is handed, not by what its prompt asks it to do. Only the coordinator holds the delegation tool, so a specialist cannot re-route — the rule holds even if a specialist is talked into trying.

Why the crew cannot move money

The brief said no refunds, cancellations, or payments. That is enforced five times over, at layers that fail independently — none of them a line of prompt text asking the model to behave.

  1. L1Nothing bound. No refund, cancel, or payment function is written anywhere in the process.
  2. L2Read-only driver. DuckDB is opened in read-only mode; a write cannot reach the data.
  3. L3Startup assertion. The registered tool set must equal a hard-coded literal, or the server refuses to start.
  4. L4PreToolUse denial. Money vocabulary and non-allowlisted tools are refused at call time.
  5. L5canUseTool gate. A second, independent runtime check that does not share code with L4.

The guarantee is tested, not asserted: injecting an issue_refund tool into the registry takes the suite from 9 passing to 7 passing and 2 failing. Then it goes back.
